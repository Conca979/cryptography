Threat Modeling

The Problem We Are Preventing: Zero-Cost Mass Scraping

Threat Vectors 1–4
Vector 1 & 2 Direct CDN Scraping & DOM Asset Extraction
  • Direct HTTP / CDN Scraping (curl, httpx): Automated scripts download raw image binaries directly from CDN endpoints at zero compute cost.
  • DOM & Network Inspection: Casual scrapers extract image URLs from <img> tags or the browser Network tab.
  • Our Defense: Scrambled image binaries stored on CDN are visually incoherent jigsaw puzzles. Direct downloads yield unusable data.
Vector 3 & 4 Unauthorized Hotlinking & Mass Piracy Syndicates
  • Unauthorized Visual Hotlinking: Pirate websites embed legitimate image URLs in external <img> tags, stealing bandwidth without custom JavaScript.
  • Mass Piracy at Scale: Crawlers harvest 50,000 chapters overnight. While a human can screenshot a single page, bulk scraping requires either heavy headless browsers or costly AI jigsaw solvers.
  • Our Defense: Breaks hotlinking completely; raises compute costs by 50x, destroying the pirate business model.
The Economic Asymmetry: Legitimate users spend < 3 ms client compute via canvas reconstruction. Attackers must spend massive CPU/GPU resources per page, eliminating zero-marginal-cost crawler economics.
Leader's Talking Points:

  • If an attacker directly extracts the URL from network inspection, they download a disjointed jigsaw puzzle.
  • Hotlinking is visually broken: third-party sites lack our session-bound client JavaScript, so hotlinked images display as scrambled tiles.
  • Emphasize the economic defense: we do not need to prevent an individual taking one screenshot; we need to make automated bulk scraping economically unviable.
Cryptographic & Engineering Dilemma

Why Traditional Encryption and Pixel Ciphers Fail

The Compression Penalty
Failure 1 Traditional Ciphers (AES/RSA)

Decrypted before rendering. Standard browsers decrypt the entire binary into a local Blob URL or memory buffer. Scrapers intercept the decrypted asset directly from memory or network cache.

Failure 2 Pixel Chaotic Ciphers (Arnold Map)

Shuffles individual pixels across the entire image. This destroys 2D spatial correlation, turning the image into uniform white noise. Huffman and LZ77 dictionary codecs completely collapse.

Failure 3 The Analog Dilemma

Any image rendered to human eyes can be captured via screenshots (PrtScn). Heavy cryptographic encryption at the transport layer is rendered useless once the image hits the display buffer.

Pixel Chaotic Permutation Individual Pixels 735.7 KB +336.7% Inflation Prohibitive CDN Bandwidth Costs
Tile-Level Transposition (Ours) Rectangular Tiles 181.9 KB +8.0% Minimal Overhead Optimal Web Production Grade
Leader's Talking Points:
  • Point out the dilemma: Why didn't we just use Arnold's Cat Map on individual pixels?
  • Look at the numbers from our actual benchmark: pixel shuffling inflates a 168 KB PNG to 735 KB (+336%)! Under WebP and JPEG it is over +400% to +650%!
  • Why? Because image compression algorithms rely on smooth color gradients between adjacent pixels. Pixel shuffling destroys spatial autocorrelation.
  • Tile transposition is the solution: it scrambles macro-positions while keeping the pixels inside each tile perfectly smooth.
Core Solution Concept

The Tile-Level Transposition Solution

Preserving Autocorrelation
The Architectural Principle Macro Disordering, Micro Smoothness
  • Grid Partitioning: Image of size W × H is divided into an M × N grid of tiles, each sized Tw × Th.
  • Indivisible Tile Blocks: Whole rectangular blocks (e.g. 34 × 34 or 48 × 32 pixels) are treated as atomic units.
  • Preserved Autocorrelation: Inside every tile, natural color gradients and spatial entropy remain 100% intact.
  • Contained Edge Cost: Sharp artificial contrast edges only exist at the M − 1 vertical and N − 1 horizontal tile boundaries.
Delivery & Reconstruction Lifecycle
  • 1. Publish Time: Python server scrambles tiles using affine modular matrix and stores ciphertext image on static CDN.
  • 2. Client Request: Web browser fetches scrambled image and loads it into an offscreen buffer.
  • 3. Dynamic Keying: Client obtains transformation parameters bound to the user session.
  • 4. Canvas Blitting: Lightweight JavaScript calculates the inverse coordinate map and blits tiles to HTML5 Canvas in < 2 ms.
Key Result: Zero visual quality loss (PSNR = ∞, MSE = 0.0), sub-3 ms reconstruction latency, and minimal compression overhead (+4% to +10%).
Leader's Talking Points:
  • Explain the workflow: image is scrambled once on the backend and cached statically on CDN.
  • The browser downloads the scrambled file and uses a fast JavaScript inverse function to assemble it into a clean canvas.
  • Because canvas blitting happens entirely on the client GPU/CPU, server overhead is zero during delivery.
  • Notice how this neatly sidesteps the analog hole: legitimate readers get instant clean viewports, while scrapers downloading raw assets get useless jigsaw tiles.
Mathematical Progression

Theoretical Evolution: From Arnold to SRT and GRT

Academic Progression Narrative
Model 0 Arnold's Cat Map
  • Strictly square matrices (N × N). Fails on non-square images (M ≠ N).
  • Decryption requires iterating forward until periodic recurrence (R rounds).
  • No algebraic inverse for non-square domains.
  • Destroys compression codecs entirely.
Model 1 (Baseline) Special Rectangular (SRT)
  • Supports arbitrary aspect ratios (M ≠ N).
  • Direct O(1) algebraic inversion (no iterative searching).
  • Minimal ALU cost (2 multiplications, 2 modulos).
  • Critical Flaw: Linear map preserves origin: [0, 0]T → [0, 0]T. Top-left tile never moves!
Model 2 (Production) Generalized Rectangular (GRT)
  • Full 4-degree-of-freedom transformation matrix G.
  • Origin Elimination: Introduces translation offset (rm, rn). (0, 0) → (rm, rn).
  • Guaranteed 100% reversible via 4 modular conditions.
  • Exact 4-stage uncoupling inverse (IGRT).
Why We Defend Both: In academic evaluation, presenting a progression from a baseline model (SRT) to a hardened solution (GRT) proves deep theoretical understanding of cryptographic trade-offs.
Leader's Talking Points:
  • This progression narrative is the backbone of our paper.
  • First, show why Arnold Cat Map is inadequate: it only works on square images and requires slow periodic recurrence to decrypt.
  • Second, introduce SRT: Lan & Wang's minimal solution for rectangular images with direct algebraic inverse. But explain its critical vulnerability: the top-left tile at (0,0) never moves!
  • Third, introduce GRT: the complete model that adds translation offset (rm, rn) to eliminate the origin anchor tile while preserving exact reversibility.

Where M and N are grid dimensions, p = gcd(M, N), h = M/p, and v = N/p.

Solvability Condition (Condition 5):
(r mod h = 0 ∨ s mod v = 0) ∧ gcd(rs + 1, v) = 1
Direct Algebraic Inverse (ISRT)
yn = (yn+1 − s · xn+1) mod N
xn = (xn+1 − r · yn) mod M

Inverts in exact O(1) time. Computes yn first, then substitutes yn to retrieve xn without modular matrix inversion.

The Fixed-Point Vulnerability:
For coordinate (0, 0): [1, r; s, rs+1] [0, 0]T ≡ [0, 0]T (mod [M, N]T). The top-left tile remains permanently stationary, serving as an anchor for scrapers.
Leader's Talking Points:
  • Notice how elegant SRT is: decryption only requires two sequential subtractions modulo N and M.
  • Why does naive inverse matrix fail on non-square domains? Because cross-modulus errors occur when M != N.
  • Condition 5 forces either r mod h = 0 or s mod v = 0, decoupling the equations.
  • Highlight the vulnerability for Member 2: because SRT is linear and homogeneous, (0,0) always maps to (0,0). This creates a stationary tile that scrapers or OCR bots can use as an anchor.

The 4 Reversibility Conditions
  • Condition 1: (b mod h = 0) ∨ (c mod v = 0) — eliminates cross-modulus shearing error.
  • Condition 2: gcd(|G|, p) = 1 — guarantees modular inverse exists modulo p.
  • Condition 3: gcd(a, h) = 1 — ensures horizontal triangular solvability.
  • Condition 4: gcd(d, v) = 1 — ensures vertical triangular solvability.
The 4-Stage Exact Inversion Pipeline
  • Stage 1 (Equilateral Inverse): Invert modulo p = gcd(M, N) to find [xp, yp]T.
  • Stage 2 (Projection Mapping): Compute projected differences [H, V]T.
  • Stage 3 (Triangular Uncoupling): Solve [xh, yv]T across Case 1, 2, or 3.
  • Stage 4 (CRT Assembly): Reassemble original coordinates: x = xp + xh · p, y = yp + yv · p.
Fixed Point Eliminated: (0, 0) → (rm, rn). Every tile moves. Attacker has zero static reference tiles.
Leader's Talking Points:
  • Explain the power of GRT: by adding (rm, rn), the top-left tile at (0,0) is displaced to (rm, rn).
  • Why does the offset not break mathematical reversibility? Because during decryption, the client simply subtracts (rm, rn) first!
  • The 4 conditions guarantee that the transformation is a true bijection across any non-square grid.
  • Stage 3 handles 3 distinct triangular cases depending on which off-diagonal element satisfies Condition 1. Our JavaScript client implements all 3 cases cleanly.
System Architecture

System Architecture & Engineering Implementation

Zero-Dependency Stack
Server-Side Engine (Python 3.10+)
  • Modules: src/cryptography/srt_server.py & grt_server.py.
  • Strict Dependencies: Standard library + Pillow (I/O) + NumPy (2D/3D array slicing).
  • Parameter Validator: Validates Conditions 1–4, bounds, and image dimension divisibility.
  • Pipeline: Slices image into M × N tiles, permutes tile indices via forward affine map, and encodes scrambled ciphertext for CDN caching.
Client-Side Engine (Vanilla JavaScript)
  • Modules: src/cryptography/isrt_client.js & igrt_client.js.
  • Runtime: Runs directly in browser on HTML5 Canvas 2D via typed Uint32Array buffers.
  • Euclidean Modulo: Custom positive modulo mod(n, m) = ((n % m) + m) % m preventing negative index bugs.
  • Lossless Blitting: Enforces ctx.imageSmoothingEnabled = false for pixel-perfect tile restoration.
Production Portability: Dual export support allows the JavaScript modules to run both in modern web browsers (window.GRT) and headlessly in Node.js for automated testing.
Leader's Talking Points:
  • Highlight our engineering discipline: zero unnecessary dependencies. No heavy npm packages, no PyTorch, no C-extensions.
  • The server scrambles once at publish time. The client descrambles in real-time in the browser.
  • Notice the JavaScript modulo fix: standard JavaScript % returns negative remainders for negative numbers, which crashes canvas lookups. Our Euclidean modulo helper guarantees positive indices.
